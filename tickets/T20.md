# T20 — Tamper alerts & tier/paywall UI

## Context
Spec §3.7 (tamper resistance): "Uninstall protection (Device Admin) + instant parent alert on
uninstall/disable attempt. Alert if VPN, accessibility service, or location is turned off;
optional auto-lock device until restored. PIN-protected settings on the child device." Spec
§3.8 (tiers): the Free/Standard/Premium table (T06). This ticket is the parent-facing surfaces
for both — the alert feed and the upgrade/paywall screens every other gated screen
(T14/T16/T17) links to.

Reuses `TamperPolicy` (T02), `DeviceEvent` types `uninstall_attempt`/`service_disabled` (T02,
dispatched real-time per T09), `Tier`/`Subscription`/`TIER_FEATURES`/`TIER_DEVICE_LIMIT` (T06).

## Requirements
In `app/src/parent/tamper/` and `app/src/parent/billing/`:

1. `TamperAlertsScreen.tsx` — feed of `DeviceEvent`s where `type` is `uninstall_attempt` or
   `service_disabled`, newest first, each showing which device/service and a timestamp; a
   toggle row wired to `TamperPolicy.autoLockUntilRestored` and `pinRequired` (saved via
   `usePolicy`, T13).
2. `PaywallScreen.tsx` — renders the 3-tier comparison table straight from
   `TIER_FEATURES`/`TIER_DEVICE_LIMIT` (T06) so it can never drift from the gating logic
   (no hand-copied feature list) — every gated screen's upsell card (T14, T16, T17) links here.
   No real payment processing — a "Contact us to upgrade" placeholder action is sufficient
   (adding a payment provider is a new vendor dependency, out of scope/escalation, same
   reasoning as elsewhere in this project) — clearly labelled as a placeholder in a code
   comment, not silently faked as a working purchase flow.
3. Tests: alert feed filters to only the two tamper event types; paywall table renders exactly
   what `TIER_FEATURES`/`TIER_DEVICE_LIMIT` contain (a snapshot-style assertion so the two
   can't silently diverge); toggles save via the expected policy shape.

## Out of scope
- Real payment/subscription processing.
- The native detection that actually produces `service_disabled` events (VPN/accessibility/
  location toggled off) — that's Android-native (T22–T24), this is display + policy-toggle only.
