# T05 — Schedules & routines engine

## Context
Spec §3.1: "Schedules/routines: homework, bedtime, mealtime, school — with tailored app/website
access per routine. Separate weekday/weekend sleep times." Plus vacation mode (§3.1: "Vacation
mode with an end date that auto-restores normal schedules"). This is pure logic, fully
unit-testable, and is the `isWithinAllowedWindow` predicate that T03's bucket engine consumes
(T03 was built against an injected function of this shape — this ticket provides the real
implementation).

Reuses `SchedulePolicy`, `RoutineType`, `VacationMode` from T02 (`packages/domain/src/types.ts`)
— restated here:
```ts
export type RoutineType = 'homework' | 'bedtime' | 'mealtime' | 'school' | 'custom';
export interface SchedulePolicy {
  id: string; type: RoutineType;
  daysOfWeek: number[]; startTime: string; endTime: string; // "HH:mm" local
  allowedCategories: string[];
}
export interface VacationMode { enabled: boolean; endDate: string | null; }
```

## Requirements
In `packages/domain/src/schedules/`:

1. `engine.ts`:
   - `isWithinAllowedWindow(schedules: SchedulePolicy[], vacation: VacationMode, categoryId:
     string, at: Date): boolean` — the exact function signature T03 expects as its injected
     predicate. If `vacation.enabled` and `vacation.endDate` is in the future, **all** normal
     schedule restrictions are bypassed (return `true` unconditionally) — this is vacation
     mode's whole purpose. If `vacation.endDate` has passed, treat as auto-expired (behave as
     `enabled: false` — do not require anything external to flip the flag; the *caller* is
     responsible for eventually persisting the auto-restore, but the pure predicate must be
     correct even before that write happens).
   - Support **separate weekday/weekend sleep times**: model this as two `bedtime`-type
     `SchedulePolicy` entries with different `daysOfWeek` sets (Mon-Thu vs Fri-Sat, say) rather
     than a special case in the engine — document this convention in a code comment and in the
     report.
   - Overlapping windows for the same category: most-restrictive wins (if any active window at
     `at` disallows the category, the result is disallowed, even if another active window would
     allow it).
   - Handle windows that cross midnight (e.g. bedtime 21:00–07:00) correctly.
2. `vacation.ts` — `shouldAutoRestore(vacation: VacationMode, now: Date): boolean` — a small
   pure helper a caller (backend cron, T09) uses to know when to flip `enabled` back to false
   and persist it.
3. `__tests__/engine.test.ts` — cover: normal week window blocks a category outside allowed
   list; vacation mode bypasses all restrictions; expired vacation end date does not bypass;
   midnight-crossing window; weekday vs weekend bedtime difference; overlapping windows
   resolve most-restrictive.

## Out of scope
- Persisting the vacation auto-restore write — that's a backend concern (T09 or a scheduled
  job), this ticket only provides `shouldAutoRestore`.
- Any UI.
