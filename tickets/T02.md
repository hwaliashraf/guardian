# T02 — Shared domain types & contracts

## Context
Establishes the canonical data model used by every later ticket (backend schema, RN UI,
domain engines). This is a foundational contract ticket — get the shapes right, since T03–T30
all build on them. Read `../LEDGER.md` for Phase-0 decisions (Supabase backend, Premium-only
VPN, real-time presence-trigger push, etc.) before starting.

`packages/domain` must have **zero** dependency on React Native or Supabase client libraries —
pure TypeScript only, importable from both the backend (edge functions) and the app.

## Requirements
In `packages/domain/` (extends root `tsconfig.base.json`, own `package.json` name
`@guardian/domain`, `src/` layout, built with `tsc`):

Create `src/types.ts` with these exact types (use `zod` — add as a dependency of this
workspace only — for runtime schemas alongside the TS types, exported as `<Name>Schema`):

```ts
export type Platform = 'android' | 'ios';
export type Tier = 'free' | 'standard' | 'premium';

export interface Family { id: string; name: string; createdAt: string; }

export interface Parent { id: string; familyId: string; email: string; }

export interface Child {
  id: string; familyId: string; name: string;
  birthdate: string; // ISO date; ageTier is derived, never stored
}

export interface Device {
  id: string; childId: string; platform: Platform; name: string; registeredAt: string;
}

export interface Subscription { familyId: string; tier: Tier; deviceLimit: number; }

// --- Policy sub-shapes ---
export interface ScreenTimePolicy {
  dailyLimitMinutes: number;
  weeklyLimitMinutes: number;
  perApp: Record<string, number>;      // appId -> minutes/day
  perCategory: Record<string, number>; // categoryId -> minutes/day
}

export interface BucketCategoryConfig {
  maxSessionMinutes: number;
  mandatoryBreakMinutes: number;
  maxSessionsPerDay?: number;
  graceFinishEnabled: boolean; // +3 min once per session
}
export interface BucketPolicy {
  perCategory: Record<string, BucketCategoryConfig>; // categoryId -> config
  default: BucketCategoryConfig; // applies to categories with no override
}

export type RoutineType = 'homework' | 'bedtime' | 'mealtime' | 'school' | 'custom';
export interface SchedulePolicy {
  id: string; type: RoutineType;
  daysOfWeek: number[]; // 0=Sun..6=Sat
  startTime: string; // "HH:mm" local
  endTime: string;   // "HH:mm" local
  allowedCategories: string[]; // categories permitted during this window; [] = none
}
export interface VacationMode { enabled: boolean; endDate: string | null; }

export interface ContentFilterPolicy {
  categories: Record<string, 'block' | 'allow'>; // see contentCategories.ts (T15) for the id list
  whitelistOnly: boolean;
  customAllowDomains: string[];
  customBlockDomains: string[];
  customBlockKeywords: string[];
  safeSearchEnforced: boolean;
  youtubeRestrictedMode: boolean;
}

export interface AppRulePolicy {
  blockedApps: string[];
  allowedApps: string[];
  blockByStoreRating: string[]; // e.g. ['17+','Mature']
}

export interface PresencePolicy {
  level0Enabled: boolean; // media/interaction heuristics
  level1Enabled: boolean; // device motion
  level2Enabled: boolean; // camera presence (Android only)
  thresholdMinutes: { level0: number; level1: number; level2: number };
  onTrigger: 'pauseTimer' | 'lockScreen' | 'both';
  refundAbandonedMinutes: boolean;
  notifyParentOnTrigger: true; // Phase-0 decision: always real-time, not configurable to off
}

export interface TamperPolicy {
  alertOnUninstallAttempt: boolean;
  alertOnServiceDisabled: boolean;
  autoLockUntilRestored: boolean;
  pinRequired: boolean;
}

export interface Policy {
  id: string; childId: string; version: number;
  screenTime: ScreenTimePolicy;
  buckets: BucketPolicy;
  schedules: SchedulePolicy[];
  vacation: VacationMode;
  contentFilter: ContentFilterPolicy;
  appRules: AppRulePolicy;
  presence: PresencePolicy;
  tamper: TamperPolicy;
  instantPause: boolean; // parent one-tap lock of all family devices
}

// --- Events & requests ---
export type EventType =
  | 'app_usage' | 'block_attempt' | 'search_query' | 'youtube_view'
  | 'new_install' | 'uninstall_attempt' | 'service_disabled'
  | 'presence_trigger' | 'location_update' | 'geofence_enter' | 'geofence_leave';

export interface DeviceEvent {
  id: string; deviceId: string; childId: string; type: EventType;
  payload: Record<string, unknown>; occurredAt: string;
}

export type RequestType = 'extra_time' | 'unblock' | 'schedule_change';
export type RequestStatus = 'pending' | 'approved' | 'denied';
export interface ChildRequest {
  id: string; childId: string; type: RequestType;
  payload: Record<string, unknown>; status: RequestStatus;
  createdAt: string; resolvedAt: string | null;
}
```

Write a `zod` schema mirroring each interface (`FamilySchema`, `PolicySchema`, etc.) in the
same file or a co-located `src/schemas.ts`, and a barrel `src/index.ts` exporting everything.

Add a `deriveAgeTier(birthdate: string, asOf?: Date): 'young' | 'preteen' | 'teen'` helper in
`src/ageTier.ts` (young: <8, preteen: 8–12, teen: 13+) with unit tests — this feeds the
age-based filter presets (spec §3.2).

## Out of scope
- No bucket/schedule/presence *engine logic* (evaluation, session tracking) — only types. That's
  T03/T04/T05.
- No content category id list — that's T15 (this ticket only types `categories` as
  `Record<string, ...>`).

## Review findings (address before DONE)

A reviewer found that the fix applied to `tsconfig.base.json` (adding `"include": []`) to make
`npx tsc -p tsconfig.base.json --noEmit` pass with zero source files does NOT actually fix the
check — it makes the base config compile zero files **permanently**, so it silently passes even
when real type errors exist anywhere in the monorepo (verified: injecting a deliberate type
error into `types.ts` still exits 0). This check is reused verbatim as a Done-when criterion in
T03 and T04, so as written every future ticket's "root check" would trivially pass regardless of
real type errors.

**Fix required:** replace `"include": []` with an `"exclude"` list instead (e.g.
`"exclude": ["node_modules", "dist", "build", "**/*.test.ts"]`), with no `"include"` override —
verified by the reviewer to still exit 0 today while actually typechecking `types.ts`,
`schemas.ts`, `ageTier.ts`, `index.ts` from the root. Apply this fix, re-verify by re-injecting
a deliberate type error temporarily and confirming `npx tsc -p tsconfig.base.json --noEmit`
now correctly fails (paste the failing output), then revert the deliberate error and confirm
it passes clean again (paste that output too) — both pieces of evidence are required this time,
not just the passing case.
