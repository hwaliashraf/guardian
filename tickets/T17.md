# T17 — Location & geofencing

## Context
Spec §3.4: "Real-time GPS location on family map, location sharing both ways. Geofences with
enter/leave alerts; 30-day location history." Gated behind `locator` feature (Standard+, T06).
No mapping vendor account exists in this environment (Google Maps/Mapbox API key) — treat the
map provider as a swappable interface, not a hard dependency, per the same "new vendor is an
escalation" principle used for blocklists/FCM elsewhere in this project.

## Requirements
Backend (`packages/backend/`):
1. `supabase/migrations/0006_geofence.sql` — `geofence { id, child_id, name, lat, lng,
   radius_meters, alert_on_enter, alert_on_leave }`.
2. `location-ingest` reuses T09's `event-ingest` function (event types `location_update`,
   `geofence_enter`, `geofence_leave` already in T02's `EventType` union) — this ticket adds
   the **server-side geofence evaluation**: `src/geofence.ts`, pure function
   `evaluateGeofences(geofences: Geofence[], point: {lat,lng}, previouslyInside: Set<string>):
   { entered: string[]; left: string[] }` (haversine distance check), called from
   `event-ingest` when a `location_update` arrives, dispatching a push (T08's `PushDispatcher`)
   for any entered/left geofence with its alert flag on. `src/__tests__/geofence.test.ts`
   covers enter/leave/no-change cases.
3. 30-day history: a query helper `getLocationHistory(childId, days=30)` reading
   `device_event` filtered to `location_update`, with a retention note — this ticket does not
   need to implement deletion of events older than 30 days (that's a data-retention job, flag
   as noticed-not-touched follow-up) but the query itself must cap the range correctly (test
   this).

Frontend (`app/src/parent/location/`):
1. `FamilyMapScreen.tsx` — gated behind `hasFeature(tier, 'locator')`. Render each child's
   latest location as a pin. **Map rendering itself uses a swappable `MapProvider` interface**
   with a simple built-in fallback renderer (plain lat/lng list + a static placeholder view,
   not a real interactive map) so the screen is real and testable without a Maps API key;
   document in `SETUP.md` under a new "Maps provider" section exactly which key/env var to add
   and which library (`react-native-maps` + Google Maps API key, most idiomatic RN choice) to
   swap in later.
2. `GeofenceEditorScreen.tsx` — create/edit/delete geofences (name, center point picked from
   the same fallback view, radius, enter/leave alert toggles).
3. `LocationHistoryScreen.tsx` — list of the 30-day history query results, grouped by day.
4. Tests: map screen upsell for non-entitled tier; geofence editor CRUD round-trip; history
   screen renders grouped results from a fixture.

## Out of scope
- Real interactive map rendering / Maps API integration — documented swap point only.
- Location history auto-deletion after 30 days — noted as follow-up.
