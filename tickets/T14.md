# T14 — Parent Usage Buckets config UI

## Context
Differentiator 2 (spec §5), Premium-gated (`usage_buckets` feature, T06). This is the config
surface for the engine built in T03 — get this right, it's the headline feature's parent-facing
control.

Reuses `BucketPolicy`, `BucketCategoryConfig` (T02/T03) and `hasFeature`/`TIER_FEATURES` (T06).

## Requirements
In `app/src/parent/buckets/`:

1. `BucketsScreen.tsx` — if `!hasFeature(tier, 'usage_buckets')`, render an upsell card (not a
   blank/broken screen) linking to T20's paywall screen; otherwise render a per-category editor
   list (reuse `usePolicy` from T13) with, per category: max session length, mandatory break
   length, optional max-sessions-per-day, grace-finish toggle — plus a `default` row applying
   to categories with no override. Inline help text explaining the short-break-doesn't-reset
   rule and the grace-finish mechanic (transparency matters here per spec's "full
   transparency" emphasis).
2. Validation: mandatory break must be > 0 if session length is set; grace finish is a toggle
   only (fixed +3 min per spec, not parent-configurable, per spec text — do not add a
   configurable minutes field here, that would be scope creep).
3. Tests: upsell shown for non-premium tier; category override list add/edit/remove round-trips
   correctly; validation blocks a zero-length mandatory break.

## Out of scope
- The bucket engine itself (already built, T03) — this is UI only, wired via `usePolicy`'s
  save path (T13) which hits T08's PUT endpoint.
- Child-facing display of buckets — T21.
