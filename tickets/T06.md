# T06 — Tier gating logic

## Context
Spec §3.8, restated verbatim (Phase-0 decision confirmed this exactly, no free VPN hook):
- **Free**: 1 device — website blocker, instant pause.
- **Standard**: up to 10 devices — app blocker, schedules, screen time, locator.
- **Premium**: up to 20 devices — VPN adult-ad shield, usage buckets, presence detection,
  per-app limits, priority support.

This is pure gating logic consumed by both backend (reject policy writes for gated features)
and UI (grey out/upsell gated controls). Uses `Tier`, `Subscription` from T02.

## Requirements
In `packages/domain/src/tiers/`:

1. `features.ts` — enumerate a `Feature` union covering every gated capability:
   ```ts
   export type Feature =
     | 'website_blocker' | 'instant_pause'
     | 'app_blocker' | 'schedules' | 'screen_time' | 'locator'
     | 'vpn_shield' | 'usage_buckets' | 'presence_detection' | 'per_app_limits'
     | 'priority_support';
   export const TIER_FEATURES: Record<Tier, Feature[]> = { /* per the list above */ };
   export const TIER_DEVICE_LIMIT: Record<Tier, number> = { free: 1, standard: 10, premium: 20 };
   ```
   Each tier's feature list must be **cumulative** (standard includes everything free has,
   premium includes everything standard has) — encode this directly (don't compute it
   implicitly) so it's easy to audit against the spec table.
2. `gate.ts`:
   - `hasFeature(tier: Tier, feature: Feature): boolean`
   - `canAddDevice(subscription: Subscription, currentDeviceCount: number): boolean`
   - `assertFeature(tier: Tier, feature: Feature): void` — throws a typed `FeatureGatedError`
     (with `{ feature, requiredTier }`) if not entitled; callers (backend policy-write
     endpoints, T08) catch this and turn it into an HTTP 403 with the same info.
3. `__tests__/gate.test.ts` — one test per feature/tier pairing from the spec table
   (free cannot use vpn_shield; standard cannot use vpn_shield/usage_buckets/
   presence_detection/per_app_limits; premium can use everything; device limit enforcement at
   1/10/20).

## Out of scope
- Billing/payment integration — spec doesn't require it for v1 logic, only the gating; no
  Stripe/payment provider in this pass (would be a new paid vendor dependency — escalation,
  not requested).
- UI paywall screens — T20.
