# T13 — Parent policy config UI: screen time limits & schedules editor

## Context
Spec §3.1: daily/weekly limits (global, per-device, per-app-category), routines (homework,
bedtime, mealtime, school) with tailored access, weekday/weekend sleep, vacation mode with
auto-restore end date.

Reuses `ScreenTimePolicy`, `SchedulePolicy`, `RoutineType`, `VacationMode` (T02, restated in
T05) and writes via T08's `PUT /policy-sync/:childId`.

## Requirements
In `app/src/parent/policy/`:

1. `ScreenTimeScreen.tsx` — form for `dailyLimitMinutes`, `weeklyLimitMinutes`, and a
   per-category minutes table (`perCategory`); saves via policy-sync PUT, shows the gated-403
   error inline if a feature isn't entitled (per T08/T06) rather than crashing.
2. `SchedulesScreen.tsx` — list + editor of `SchedulePolicy` entries: routine type picker
   (`homework`/`bedtime`/`mealtime`/`school`/`custom`), days-of-week multi-select, start/end
   time pickers, allowed-categories multi-select. Explicitly supports adding **two** `bedtime`
   entries (weekday set + weekend set) per T05's documented convention — UI copy should call
   this out ("Weekday bedtime" / "Weekend bedtime" as two rows) rather than exposing the raw
   list abstraction.
3. `VacationModeScreen.tsx` — toggle + end-date picker; on save, PUTs `vacation: { enabled:
   true, endDate }`. Shows current state (active until <date>, or inactive).
4. Shared `usePolicy(childId)` hook (read + optimistic-update + save) reused by T14/T15/T16.
5. Tests: schedule form round-trips a `SchedulePolicy[]` correctly (add/edit/remove entries);
   screen-time save calls PUT with the expected partial-policy shape; vacation toggle disables
   the end-date field when off.

## Out of scope
- Usage Buckets config (session/break/grace) — T14.
- Content filtering, app rules — T15/T16.

- [ ] Two-bedtime-entries pattern demonstrated in a test (weekday vs weekend).
