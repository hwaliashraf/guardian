# T18 — Monitoring & reports UI

## Context
Spec §3.5: "Activity timeline: app usage, browsing history, searches, blocked attempts. YouTube
video history (titles/links of watched videos). Weekly digest email/notification to parents."
(Social media conversation monitoring is explicitly out of scope per spec §3.5/§10 — do not
build anything for it.)

Reuses `DeviceEvent`/`EventType` (T02) and `buildWeeklyDigest`/`DigestSummary` (T09).

## Requirements
In `app/src/parent/reports/`:

1. `ActivityTimelineScreen.tsx` — chronological feed of a child's `DeviceEvent` rows
   (`app_usage`, `block_attempt`, `search_query`, `youtube_view`), filterable by type, newest
   first, paginated (simple offset/limit, no infinite-scroll library needed).
2. `YouTubeHistoryScreen.tsx` — filtered view of `youtube_view` events showing title/link from
   `payload` (document the expected `payload` shape: `{ title: string; url: string;
   watchedAt: string }` — this is the contract the Android accessibility-based capture in T24
   must produce; call this out explicitly since T24 is written after this ticket and must match
   it).
3. `WeeklyDigestScreen.tsx` — renders the latest `digest` row's `DigestSummary` (from T09) in a
   readable summary layout (totals by category, block-attempt count, top blocked domains,
   YouTube count).
4. Tests: timeline filters correctly by event type; YouTube history renders title/link from
   fixture payloads matching the documented shape; digest screen renders a fixture
   `DigestSummary` correctly.

## Out of scope
- Social media monitoring (spec explicitly defers to v2/out of scope).
- Any event capture itself — that's native (T24) or backend (T09) work; this is display only.
