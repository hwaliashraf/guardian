# T29 — CI workflow + SETUP.md consolidation

## Context
Final housekeeping ticket before integration verification (T30). By this point, every prior
ticket has appended its own section to `SETUP.md` (Java/Android SDK, Docker, Supabase CLI,
FCM credentials, Maps provider, TFLite model, Xcode/CocoaPods, Apple entitlement). This ticket
sanity-checks that file for completeness/consistency and adds a CI workflow that runs
everything actually verifiable in a hosted CI runner (lint/typecheck/test across workspaces —
NOT the native builds, which need the same missing toolchains a CI runner also wouldn't have
by default without extra setup steps).

## Requirements
1. Read the current `SETUP.md` top to bottom. Fix any placeholder `TBD` sections a prior
   ticket forgot to fill in by cross-referencing that ticket's file under `tickets/` for what
   it should have written (do not invent new content — pull from the corresponding ticket's
   "Context"/"Requirements" if a section was missed, and note in the report which ticket's gap
   this was, since that's useful signal about executor drift).
2. Add a top-level "Quick start" section to `SETUP.md`: the minimal sequence to get the
   verifiable parts running locally (`npm install`, `npm run typecheck`, `npm test`, and
   `supabase start && supabase db reset` if Docker's available).
3. `.github/workflows/ci.yml` at the project root (or the repo root if this monorepo's CI
   conventions live there — check `find .. -maxdepth 3 -iname "*.yml" -path "*workflows*"`
   first and follow whatever convention already exists rather than inventing a second one;
   note in the report which path was used and why): a workflow triggered on changes under
   `projects/parental-app/**` running `npm ci`, `npm run lint`, `npm run typecheck`,
   `npm test --workspaces --if-present`. Do not include native Android/iOS build steps (no
   Java/signing setup in a hosted runner without significant extra work not requested here) —
   note this scoping explicitly in a workflow comment.
4. Cross-check: every `packages/domain` module built across T02-T27 (bucket engine, presence
   evaluator, schedule engine, tier gating, content categories, VPN/text-heuristic decision
   ports, geofence evaluator, content-blocker rules, native-port spec test) has at least one
   test file and none were accidentally left out of the root Jest config — run
   `npx jest --listTests` from the project root and paste the full list in the report as
   evidence of coverage breadth (not asserting correctness, just that nothing is orphaned).

## Out of scope
- Native build CI (documented as a known gap, not built).
- Deployment pipelines (Supabase project deploy, app store submission automation) — none of
  that infrastructure exists yet per this project's scope.

## Done when
- [ ] `SETUP.md` has no remaining `TBD` placeholders (or each remaining one is justified in the

- [ ] `.github/workflows/ci.yml` (or wherever the repo's convention places it) exists and its
      YAML is at least syntactically valid (`python3 -c "import yaml,sys;
      yaml.safe_load(open('path'))"` or equivalent — paste output).
