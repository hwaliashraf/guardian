# T23 — Android native: AccessibilityService

## Context
Spec §4, Layer 3: "The accessibility service watches on-screen text in third-party apps for
adult-ad keyword patterns; on match, the screen is covered with a block overlay and the event
is logged." Spec §3.5: "YouTube video history (titles/links of watched videos)." Spec §3.7:
"Alert if VPN, accessibility service, or location is turned off." Spec §6 Level 0 presence
signal ("no touch/scroll/key input... distinguish watching video via audio-focus") is also most
naturally sourced from this same service (foreground-app + input-activity observation) — this
ticket produces the raw signal, T21's `useLocalBucketEngine` (already built) consumes it via
whatever bridge event this ticket emits.

**Same environment caveat as T22**: no Java here, this Kotlin code is written for real but
unverified; see `SETUP.md`.

Contract this ticket MUST satisfy exactly (restated from T18, which was written first and
depends on this shape): `youtube_view` `DeviceEvent.payload` must be
`{ title: string; url: string; watchedAt: string }`.

## Requirements
In `app/android/app/src/main/kotlin/com/guardian/accessibility/`:

1. `GuardianAccessibilityService.kt` — extends `AccessibilityService`; on
   `TYPE_WINDOW_STATE_CHANGED`/`TYPE_WINDOW_CONTENT_CHANGED` events:
   - Tracks current foreground package name (feeds T24's usage accounting via a shared
     broadcast/bridge — document the IPC mechanism chosen, e.g. a `LocalBroadcastManager`
     intent or a shared singleton, and use the same one T24 will listen on).
   - Scans visible `AccessibilityNodeInfo` text against a keyword list (`AdKeywords.kt` —
     define a starter list of adult-ad-pattern keywords/regexes with a comment that this list
     is tunable/extensible) — on match, requests a system-alert-window block overlay
     (`BlockOverlayView.kt`) and emits a `block_attempt` `DeviceEvent`.
   - When the foreground package is a known YouTube package id, attempts to read the visible
     video title node text and the current video id (best-effort from the accessibility tree —
     document that this is inherently best-effort/version-fragile, a known limitation, not
     silently pretended to be 100% reliable) and emits a `youtube_view` event matching the
     exact payload contract above.
   - Tracks input-activity recency (last `TYPE_VIEW_SCROLLED`/touch-adjacent event timestamp)
     and audio-focus state (via `AudioManager.OnAudioFocusChangeListener`) and periodically
     emits a presence-signal bridge event shaped to match T04's `PresenceSignalSample.level0Idle`
     /`foregroundAppCategory` fields exactly (restate: `{ level0Idle: boolean;
     stillPromptTimedOut: boolean; level1Still: boolean; level2FaceSamples: boolean[];
     foregroundAppCategory: string; now: string }` — this service only ever fills
     `level0Idle`/`foregroundAppCategory`/`now`; `level1Still` comes from T24 or a motion
     sensor, `level2FaceSamples` from T25 — document that the bridge event is a **partial**
     sample and the JS/RN side (T21, already built) is responsible for merging partial samples
     before calling `evaluatePresence`; if T21 didn't anticipate partial-sample merging,
     flag this as a `RISK:` note for the orchestrator since it may require a small T21 patch).
2. `AndroidManifest.xml` + `res/xml/accessibility_service_config.xml` — service declaration,
   `canRetrieveWindowContent`, event types, and the required user-facing description string
   (leave a `// see T28 compliance doc` marker, don't duplicate copy here).
3. Tamper signal: detect `onInterrupt()`/service-disabled callbacks and emit a
   `service_disabled` `DeviceEvent` (T02 type) — this is the accessibility half of spec §3.7's
   tamper alert (VPN half already in T22, Device Admin half in T24).
4. Same pattern as T22: port the pure keyword-match decision logic into
   `packages/domain/src/vpn/textHeuristic.ts` (or a new `packages/domain/src/tamper/` module —
   pick the more fitting location and say which) with full Jest tests, as the verifiable spec
   of the Kotlin logic.
