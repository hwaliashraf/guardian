# T09 — Event ingestion + weekly digest + vacation auto-restore

## Context
Spec §3.5: "Activity timeline: app usage, browsing history, searches, blocked attempts... Weekly
digest email/notification to parents." Spec §6 presence bonus: real-time push per Phase-0
decision (LEDGER.md) on every presence trigger — this ticket wires the presence-trigger
`DeviceEvent` (from T04's `evaluatePresence` output) to an actual push via T08's
`PushDispatcher`. Spec §3.1 vacation mode "auto-restore" — this ticket wires T05's
`shouldAutoRestore` pure helper to a real scheduled job.

Reuses: `DeviceEvent`/`EventType` (T02), `PushDispatcher` (T08), `shouldAutoRestore` (T05).

## Requirements
In `packages/backend/supabase/functions/` and `packages/backend/src/`:

1. `event-ingest/index.ts` — `POST /event-ingest` — body is one or more `DeviceEvent`s from a
   child device; inserts into `device_event` table (from T07). If `type === 'presence_trigger'`,
   immediately calls `PushDispatcher.send` to the child's parent devices (real-time, per
   Phase-0 decision — no batching/digest-only path for this event type). If
   `type === 'uninstall_attempt' || type === 'service_disabled'`, also dispatch immediately
   (spec §3.7 tamper alerts are explicitly real-time in the spec, independent of the presence
   decision).
2. `src/digest.ts` — pure function `buildWeeklyDigest(events: DeviceEvent[], childId: string,
   weekStart: Date): DigestSummary` (`DigestSummary` = totals by category, block-attempt count,
   top blocked domains, YouTube videos watched count) — testable without a DB.
3. `digest-cron/index.ts` — edge function intended to run on a Supabase cron schedule
   (document the `supabase/config.toml` cron entry, e.g. weekly), queries the past week's
   `device_event` rows per child, calls `buildWeeklyDigest`, dispatches one push +
   logs a `digest` row (new migration `0004_digest.sql`: `digest { id, child_id, weekStart,
   summary jsonb, sentAt }`).
4. `vacation-cron/index.ts` — edge function (also cron-scheduled) that loads every `Policy`
   with `vacation.enabled = true`, calls `shouldAutoRestore`, and for any that should restore,
   sets `vacation.enabled = false`, bumps `version`, dispatches a push (reuses T08's
   policy-write-and-notify path — import its pure module rather than duplicating logic).
5. Tests in `packages/backend/src/__tests__/`: `digest.test.ts` (digest math correctness against
   a fixture event list), `eventIngest.test.ts` (presence/tamper events trigger dispatch,
   ordinary `app_usage` events do not), `vacationCron.test.ts` (expired vacations restore,
   active ones don't).

## Out of scope
- Actual cron scheduling infrastructure verification (Supabase cron requires a deployed
  project) — document the `config.toml` cron syntax and note in `SETUP.md` that this needs a
  deployed Supabase project to actually fire on schedule; the functions themselves are real
  and unit-tested, just not verified running on a live schedule.
- Email delivery for the digest (spec says "email/notification" — this pass implements the
  push/notification path only via T08's dispatcher; email is a new vendor dependency, not
  added without approval — note as a noticed-not-touched item).
