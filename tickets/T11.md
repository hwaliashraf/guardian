# T11 — React Native app shell, navigation & Supabase client wiring

## Context
Spec §2.2: "App shell / UI: React Native (single codebase, parent + child apps as two build
targets or one app with role selection)." This ticket creates the actual RN project — every
later UI ticket (T12–T21) builds screens inside it. Because later tickets need real native
modules (VpnService, AccessibilityService, CameraX, Device Admin — Android; NEDNSSettingsManager,
FamilyControls, Safari Content Blocker — iOS), this must be a **bare** React Native project
(community CLI), not an Expo-managed one.

**Network/tooling fallback, try in order, report which path was actually used:**
1. `npx @react-native-community/cli init app --directory app --skip-install` (or current
   equivalent) inside `projects/parental-app/`, then `npm install` at the workspace root.
2. If that fails (no network, registry unreachable, etc.): hand-author the minimal bare-RN
   project structure yourself — `app/package.json` (react, react-native, typescript deps
   pinned to current stable versions), `app/index.js`, `app/App.tsx`, `app/android/` and
   `app/ios/` **directory placeholders** with a `README.md` in each stating "run `npx
   react-native init` (or `npx react-native-community-cli-android`/`ios` platform templates)
   here once network access is available — the app/src TypeScript code in this repo does not
   depend on the native project files existing to be linted/typechecked/unit-tested." Add the
   exact fallback command to `SETUP.md` under a new "React Native native project scaffolding"
   section. Either way, the goal is that `app/src/**/*.tsx` (the actual product code) is real,
   typed, and testable regardless of whether the native Android/iOS project folders were
   generated.

## Requirements
Inside `app/` (npm workspace member):

1. TypeScript strict, extends root `tsconfig.base.json`. React Navigation
   (`@react-navigation/native` + native-stack) for routing.
2. `src/supabaseClient.ts` — thin wrapper around `@supabase/supabase-js`, reading
   `SUPABASE_URL`/`SUPABASE_ANON_KEY` from env (react-native-config or `.env` — pick one, note
   choice), pointed at `http://localhost:54321` (Supabase CLI default) for local dev.
3. `src/navigation/RootNavigator.tsx` — on first launch, a **role-selection** screen
   ("I'm a parent" / "I'm on my child's device"); persist the choice (AsyncStorage) so
   subsequent launches skip straight to the right navigator: `ParentNavigator` (stack: Login →
   Dashboard, stubs for now, filled in by T12+) or `ChildNavigator` (stack: PairDevice →
   Dashboard, stubs for now, filled in by T21). Use React Navigation nested navigators, not a
   from-scratch router.
4. `src/auth/` — screens/hooks calling T10's `auth-flows` edge function
   (`useSignUp(consentAccepted)`, `usePairDevice(code)`), with basic form validation.
5. Barrel exports so later tickets can add screens without restructuring navigation
   (`ParentNavigator` and `ChildNavigator` each export a `Stack.Screen` list that later tickets
   append to — document the exact append pattern in a code comment since T12–T21 depend on it).
6. Jest + `@testing-library/react-native` configured for `app/`; one smoke test rendering
   `RootNavigator` and asserting the role-selection screen shows both options.
