# T24 — Android native: Device Admin, UsageStatsManager & local enforcement

## Context
Spec §3.7: "Uninstall protection (Device Admin)... instant parent alert on uninstall/disable
attempt... optional auto-lock device until restored. PIN-protected settings." Spec §3.3:
"New-app-install alerts to the parent." Spec §7: "Offline-first enforcement: all blocking and
bucket logic runs locally... UsageStats + Bucket engine (local, offline-capable)." This ticket
is where T03's already-built-and-tested `BucketEngine` and T05's schedule engine actually run
against real device usage data and real screen-lock enforcement, closing the loop that T21's
JS-side ticking clock approximated.

Same environment caveat as T22/T23 (no Java — written for real, unverified here).

Contract this ticket MUST satisfy: `InstalledApp { appId, name, storeRating: string|null }`
(defined in T16, added to `packages/domain/src/types.ts`) is the shape T16's
`useInstalledApps` hook expects to eventually consume — this ticket is the real producer T16
documented as a future swap-in.

## Caller contract for ending a session (orchestrator-resolved, see LEDGER.md T03 entry)
The Kotlin port of the bucket engine (`NativeBucketEngine.kt`, required below) must mirror the
same rule T21 was patched with: only finalize/end a session (fold elapsed into daily usage,
open the mandatory-break lockout) when the session's own cap is genuinely reached — never on a
trivial screen-off/app-background blip. A short pause must leave the in-memory session's
elapsed-since-start calculation untouched (continuous wall-clock time, not reset), exactly
matching T03's `BucketEngine.tick()` semantics, so a 2-minute phone-lock mid-session never
triggers the mandatory-break lockout.

## Requirements
In `app/android/app/src/main/kotlin/com/guardian/deviceadmin/` and
`app/android/app/src/main/kotlin/com/guardian/usage/`:

1. `GuardianDeviceAdminReceiver.kt` — extends `DeviceAdminReceiver`; implements
   `onDisableRequested`/`onDisabled` to emit an `uninstall_attempt`/`service_disabled`
   `DeviceEvent`, and exposes lock-now capability (`DevicePolicyManager.lockNow()`) called by
   the local bucket engine when a session cap is hit or a presence trigger's `onTrigger`
   includes `lockScreen`.
2. `UsageAccountant.kt` — wraps `UsageStatsManager` to (a) query installed apps + their
   Play Store content rating where obtainable (best-effort — Android doesn't universally
   expose store rating via `PackageManager`; document this as a real limitation, and fall back
   to a manual per-app rating field the parent can set in T16's UI if the OS doesn't supply
   one — note this as a `RISK:`/limitation for the report, not silently glossed over), producing
   `InstalledApp[]` matching T16's exact shape; (b) poll foreground-app usage stats and feed
   T03's `BucketEngine` (via a native port or, more practically, drive it through a background
   `WorkManager`/foreground-service loop that calls into a small Kotlin reimplementation of
   the *session/tick* decision — **prefer** re-using the exact TS logic isn't possible in
   Kotlin directly, so this ticket must port `BucketEngine`'s tick/start/end logic to Kotlin as
   `NativeBucketEngine.kt`, mirroring T03's rules exactly (restate them here in full): total
   daily/weekly caps, max session length, mandatory break with the short-break-does-not-reset
   rule, session count cap, 5-min/1-min warnings, one-time +3min grace finish, category
   overrides. Add `NativeBucketEngine` unit tests as **Kotlin** tests — cannot run here, but
   write them for real; and additionally mirror the same rule set into a
   `packages/domain/src/buckets/nativePortSpec.test.ts` doc-as-test (a Jest test that encodes
   the same table of rule-name → expected-behavior as literal assertions against T03's actual
   `BucketEngine`, serving as the canonical, runnable cross-check that the Kotlin port's spec
   didn't drift from T03) so at least the *rules* are re-verified even though the *Kotlin
   implementation* of them isn't runnable here.
3. `InstalledAppsModule.kt` / `UsageModule.kt` — RN native module bridges exposing
   `getInstalledApps()`, `lockDevice()`, `getUsageToday()` to JS.
4. New-install detection: `PackageAddedReceiver.kt` (`BroadcastReceiver` on
   `ACTION_PACKAGE_ADDED`) emitting `new_install` `DeviceEvent`s (feeds T16's
   `InstallAlertsScreen`, already built).
5. `AndroidManifest.xml` additions: device admin receiver declaration + policy XML, uninstall
   protection disclosure marker (`// see T28`).
