# T15 — Content category list & content-filtering config UI

## Context
Spec §3.2: "DNS + browser-level web filtering with 30+ categories (adult, porn, violence,
gambling, advertisements, social, games, etc.). Age-based filter presets (auto-configured from
child's age). Whitelist-only mode for young children. Custom allow/block lists for domains and
keywords. Enforced SafeSearch on Google/Bing/DuckDuckGo and Restricted Mode on YouTube."

Phase-0 decision (LEDGER.md): Chrome + DNS only, no bundled browser this pass — this UI
configures the **policy** (which categories/domains/keywords are blocked, SafeSearch/YouTube
enforcement flags); the actual DNS-level enforcement is native (T22 Android VPN, T26 iOS DNS
profile) and reads this same policy.

## Requirements
0. **Reconcile with T04's placeholder video-category set.** T04 (presence detection) needed to
   know which foreground-app categories are "video-like" (to gate its Level-0 no-touch trigger
   so it doesn't false-fire during legitimate video watching) before this ticket's canonical
   category list existed, and used a placeholder: `VIDEO_LIKE_CATEGORIES = new
   Set(['video_streaming', 'video', 'youtube'])` in
   `packages/domain/src/presence/evaluator.ts`. Once you define the real `CONTENT_CATEGORIES`
   list below, update that constant in `evaluator.ts` to use your actual video-related category
   id(s) exactly (e.g. just `'video_streaming'` if that's the only one), and add/adjust a test
   in `packages/domain/src/presence/__tests__/evaluator.test.ts` confirming the reconciled id
   still gates correctly. Note this reconciliation explicitly in your report.
1. `packages/domain/src/contentCategories.ts` — the canonical category id list (this is the
   contract every other ticket touching `ContentFilterPolicy.categories` must use). Define
   **32** categories as a `const CONTENT_CATEGORIES` array of `{ id, label, defaultBlockedFor:
   ('young'|'preteen'|'teen')[] }`:
   `adult, pornography, nudity, violence, gambling, weapons, drugs, alcohol_tobacco,
   hate_speech, self_harm, dating, gore, advertisements, adult_ad_networks, trackers,
   malware_phishing, proxy_vpn_bypass, social_media, gaming, video_streaming, messaging,
   file_sharing, torrents, news, shopping, forums_chat, adult_ad_networks_2 (remove duplicate —
   just ensure the final list has no dupes and totals >=30; adjust naming as needed),
   pornography_ai_generated, cryptocurrency, job_search, education, search_engines,
   productivity`. (Exact final list is this ticket's call as long as it's >=30 entries, covers
   every example the spec names verbatim — adult, porn, violence, gambling, advertisements,
   social, games — and each entry has a sensible `defaultBlockedFor` derived from the T02
   `deriveAgeTier` bands. Document the final list in the report.)
   Add `getAgeBasedPreset(ageTier): Record<string, 'block'|'allow'>` pure function + tests.
2. In `app/src/parent/contentFilter/ContentFilterScreen.tsx`:
   - Category grid (toggle block/allow per category), pre-populated via
     `getAgeBasedPreset(deriveAgeTier(child.birthdate))` on first load for a child with no
     existing `ContentFilterPolicy`.
   - "Whitelist-only mode" toggle: when on, every category defaults to blocked except entries
     explicitly added to `customAllowDomains` — UI must make clear this is a stricter mode, not
     just another category toggle.
   - Custom allow/block domain + keyword list editors (add/remove rows).
   - SafeSearch-enforced / YouTube-restricted-mode toggles.
   - Saves via `usePolicy` (T13) → T08's PUT endpoint.
3. Tests: age-preset applied correctly per age tier; whitelist-only mode UI state; custom
   list add/remove round-trip; category grid covers all 32 ids from `CONTENT_CATEGORIES`.

## Out of scope
- Actual DNS/browser enforcement — T22 (Android), T26 (iOS) consume this policy, this ticket
  only edits and persists it.
- ML image scanning config — that's a device-side behavior (T25's TFLite hook), no parent
  config surface required by the spec beyond the category toggles already covered here.
