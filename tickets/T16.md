# T16 — Parent app management UI

## Context
Spec §3.3: "Block/allow installed apps; preemptive blocking of apps by store rating (e.g.,
block all 17+/Mature by default). Per-app time limits (a Mobicip weak spot — we do it properly,
per app not just per category). New-app-install alerts to the parent." Per-app *time limits*
are already covered by `ScreenTimePolicy.perApp` (T13's ScreenTimeScreen) — this ticket covers
block/allow + store-rating + install alerts only, to avoid duplicating T13.

Reuses `AppRulePolicy` (T02) — `{ blockedApps, allowedApps, blockByStoreRating }` — and
`hasFeature(tier, 'app_blocker')` (T06, Standard+).

## Requirements
In `app/src/parent/appManagement/`:

1. `AppManagementScreen.tsx` — gated behind `app_blocker` (upsell card if Free tier, matching
   T14's upsell pattern for consistency). Renders:
   - The child device's installed-app list (this ticket defines the **shape** the device
     reports — `InstalledApp { appId, name, storeRating: string|null }` — add this type to
     `packages/domain/src/types.ts` alongside the existing types, since T02 didn't anticipate
     it; note this addition explicitly in the report as a contract change future tickets must
     be aware of). Each row: block/allow toggle.
   - Store-rating quick-block: multi-select of rating tiers (`'4+'|'9+'|'12+'|'17+'|'Mature'`)
     with a default preset of `['17+','Mature']` checked, matching the spec's "block all
     17+/Mature by default" line.
   - Since no real device is paired to report installed apps in this environment (no Android
     device, per LEDGER.md), the installed-app list must come from a **mocked data source**
     behind the same interface a real device-reported list would use (`useInstalledApps(childId)`
     hook backed by a fixture in dev/test, swappable for a real `device_event`-sourced query
     later) — do not block this ticket on having a real device; document the swap point clearly.
2. `InstallAlertsScreen.tsx` — feed of `DeviceEvent` rows where `type === 'new_install'`,
   newest first, with a "block this app" quick action wired to the same `AppRulePolicy` save
   path.
3. Tests: rating quick-block defaults to 17+/Mature checked; toggling an app updates
   `blockedApps`/`allowedApps` correctly (mutually exclusive — an app can't be in both lists,
   enforce this in the save logic); install-alerts feed renders and quick-block action works.

## Out of scope
- Real installed-app reporting from an Android device — that requires T24's
  `UsageStatsManager`/package-manager native module on a real device; this ticket's mocked
  data source is the documented seam for later wiring, not implemented here.
